# Object-Oriented Programming Interview Preparation

This knowledge base is built for campus, SDE, backend, and product-company interviews. It teaches OOP as a way to model behaviour and manage change—not just four definitions to memorize.

## Learning path

| Stage | Chapters | Outcome |
|---|---|---|
| Foundations | 01–05 | Explain objects, classes, pillars, and relationships |
| Design | 06–10 | Choose interfaces, SOLID principles, and patterns |
| Language depth | 11–16 | Handle lifecycle, generics, equality, concurrency, Java/Python |
| Production thinking | 17–20 | Model real systems, test design, read UML, connect to system design |
| Practice | 21 | Answer exactly 100 interview questions |

## Speakable interview pattern

**Definition → Why → How → Example → Trade-off.** For example: “Encapsulation bundles state with controlled operations. It protects invariants, so callers cannot put an object into an invalid state. A `BankAccount.withdraw` method validates balance instead of exposing a public mutable field.”
